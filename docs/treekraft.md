# 🌲 TREEKRAFT — Универсальная документация

**Релиз:** `u1` (пакет `1.0.0`)
**Команд:** **2963** (distinct `~handler`-ов: `starts_with`/`==` + макро-определения
вида `u1!("~name(", ...)` — их ~1800, первый паттерн их не видит;
точный счёт: `tools\count commands.ps1`; полный список: `docs/COMMANDS.md`)
**Модулей:** 57 (`src/commands`)
**Платформа:** Windows (x86_64) + Linux
**Язык реализации:** Rust

TreeKraft — интерпретируемый язык с синтаксисом, похожим на Python, и встроенной
2D-графикой (minifb), SQLite, HTTP-сервером и TUI. Все команды вызываются с `~`
(`~len(x)`) и **без** `~` (`len(x)` — эквивалентно). `print()` выводит с переводом строки.

---

## 1. Быстрый старт

| Действие | Команда |
|---|---|
| Запуск REPL | `treekraft` |
| Запуск скрипта | `treekraft hello.tk` |
| Скрипт с аргументами | `treekraft hello.tk arg1 arg2` (внутри `~args`) |
| Windows-сборка | `cargo build --release` → `target\release\treekraft.exe` |
| Linux-сборка (WSL) | `cargo build --release` → `cp target/release/treekraft target/linux/treekraft` |
| Прогнать все тесты | `powershell -ExecutionPolicy Bypass -File "tools\run tests.ps1"` |
| Точный счёт команд | `powershell -ExecutionPolicy Bypass -File "tools\count commands.ps1"` |

Пример программы:

```python
noecho on
x = 10
print(~square(5))          # 25
print("Привет, " + ~upper("мир"))
for i in range(1, 6):
    print(i * i)
```

## 2. Возможности

- **2D-графика (minifb):** окно, спрайты, анимации, карты, камера, коллизии, частицы, физика.
- **SQLite:** создание/открытие БД, таблицы, запросы, дамп.
- **HTTP-сервер:** роуты, статика, JSON, формы.
- **TUI:** полноэкранный текстовый интерфейс, окна, кнопки, ввод.
- **REPL** с подсветкой ошибок и отладкой.
- **Фичи языка:** `elif`, `switch`, побитовые операции, деструктуризация, методы,
  именованные аргументы, замыкания, генераторы, try/catch.
- **Списки/словари:** стеки, очереди, сеты, срезы, comprehensions.
- **2963 команды** в 57 тематических модулях (полный список: `docs/COMMANDS.md`).

## 4. Тестирование

`tools\run tests.ps1` — прогоняет сюиту из `tests/` (correctness, stress, bench,
error-кейсы) и пишет `tests/RESULTS.md`. Отдельные проверки: `tools\test tkp.ps1`
(пакеты), `tools\test build.ps1` (сборка exe), `tools\count commands.ps1` (счёт),
`tools\test diff.ps1` — дифференциальные тесты: один скрипт через байткод и через
медленный интерпретатор (`TREK_SLOW=1`), выводы обязаны совпасть (53 кейса:
арифметика, циклы, break/continue, лямбды, ошибки, import с неймспейсом).

### Семантика ошибок (u1)
- Два пути исполнения (байткод и slow) дают одинаковые ошибки: деление/модуло
  ноля, неверная арность, отсутствующие ключи/индексы, вызов несуществующего —
  всё это ошибки в ОБОИХ путях (раньше slow молча печатал сырой текст).
- `break`/`continue` вне цикла — ошибка (`break outside loop`), а не тишина.
- `import "lib.tk" as ns` собирает модуль из переменных файла (`export z`
  помечает; без `export` — всё, что создал файл); переменные библиотеки НЕ текут
  в глобал; ошибка внутри библиотеки прерывает импорт. Чтение: `ns.z`.
- Известное поведение (не баг): голый вызов неизвестного БЕЗ `call`
  (`print(foo(1))`) в slow-пути даёт сырой текст — отличить вызов от текста
  со скобками дёшево нельзя; с явным `call` — ошибка в обоих путях.

### tkp — пакетный менеджер (CLI, `src/main/run.rs`)

GitHub выступает сервером: пакет — это репозиторий `<ник>/<имя>`, в корне которого
лежит `<имя>.tk` (однострочные `def`/`~def` и команды). Установка качает
`raw.githubusercontent.com/<ник>/<имя>/<ветка>/<имя>.tk`.

```
tkp install ник/имя[@ветка]   # ветка/тег по умолчанию: main
tkp update [ник/имя]          # переустановить всё (по сохранённому тегу) или один
tkp remove имя
tkp list                      # имя -> путь @ветка
tkp path имя
```

Хранилище: `~/.treekraft/pkgs/<имя>.tk` + реестр `~/.treekraft/pkgs/registry.json`
(формат `{"имя": {"nick":..., "path":..., "tag":...}}`, читается и старый строковый).
Использование пакета в скрипте: `~import_pkg("имя")` (читает файл напрямую и исполняет;
ошибки импорта не скрываются). Из скрипта доступны и `~trek_pkg install/list/remove/...`.

Замечание по дизайну: полный цикл (install/update/list/path/import/remove) покрыт
интеграционным тестом `tools/test tkp.ps1` (локальный HTTP-сервер через TREK_TKP_BASE,
mimic raw.githubusercontent.com; без python тест пропускается).

### build — компиляция .tk → .exe (CLI, `src/main/run.rs`)

`treekraft build app.tk [-o app.exe]` — копия собственного бинарника (stub) + payload
в хвосте: `[stub]["TREK1" + исходник][len:u64|flags:u8|резерв:u64|магия "TREKEXE!"]`.
Исходник лежит открыто (защиты нет сознательно: рантайм open source, любая схема
вскрывалась бы чтением кода расшифровки).

Собранный exe исполняет встроенный скрипт и игнорирует обычные CLI-аргументы.
Размер ≈ размер treekraft.exe (~12 МБ). Покрыто интеграционным тестом
`tools/test build.ps1` (сборка/запуск, обычный запуск `.tk` не сломан).

### test — тест-раннер (CLI, `src/main/run.rs`)

`treekraft test a.tk [b.tk ...]` — прогоняет файлы в изолированных VM и печатает
сводку (файлы ok/fail, asserts ok/fail, время). Exit-код 0 — всё зелёное, 1 — есть
падения/ошибки (годится для CI).

Ключевое отличие от обычного запуска: флаг `VM::test_continue` — упавший `assert_*`
не прерывает скрипт, а пишется в отчёт (`✗`), и прогон идёт дальше, собирая ВСЕ
падения за раз. Жёсткая ошибка (не assert) файл всё равно обрывает и помечается
ERROR. Обычный запуск `treekraft file.tk` не менялся (рвётся на первом assert).
